## What exists now

All paths are under `be/`. No application code and no migrations changed.

**`tests/integration/test_lifecycle_characterization.py`** — six strict xfail tests, each the target
behaviour of one defect. Shared setup: fixture `library_run` (library plan `Upper` / rest / `Lower`,
two microcycles starting at `FROZEN_TODAY`). Only `AssertionError` raised **outside**
`setting_up()` counts as the expected failure; setup assertion errors become `SetupFailed` and fail
the test (`raises=AssertionError` alone would not do that, because the builders assert too).

**`scripts/run_plans_preflight.sql`** — the five checks of `02` §4.1 as **one read-only `SELECT`**
(CTEs, then `ORDER BY`). Zero rows = pass. Columns: `check_no`, `check_name`, `plan_run_id`,
`revision_id`, `entity_kind` (`workout_unit` | `exercise_slot`), `track_ids int[]`,
`entity_ids int[]`. It runs on the schema before and after 0018. Command for the human (also in the
file header):

```bash
docker exec -i -e PGOPTIONS='-c default_transaction_read_only=on' <postgres container> psql -X -v ON_ERROR_STOP=1 -U <user> -d <database> < be/scripts/run_plans_preflight.sql
```

How the checks read the design:

| Point | Implemented as |
| --- | --- |
| Which runs | Only `run_plan_id IS NULL` (read through `to_jsonb`, so a missing column counts as NULL). |
| Used revisions of a run | References F2, F3 (via day), F6, F12, F13, as in `02` §4.2. |
| "Latest used" revision | Greatest first-use microcycle ordinal, then `revision_no`, then id. |
| Track → unit/slot in a revision | The bound id(s) (sessions / exercise prescriptions); otherwise by the ordinal in `day:N` / `slot:N`, the slot under the workout track's unit. |
| Check 2 | Also reports a key that is not `day:N` (with `revision_id` NULL) and a session whose day and unit belong to different revisions. |
| Check 4 | **Every** unit and slot, including a slot without a DEFAULT variant (run creation gives such a slot no track). |

One defect can raise several checks (for example a re-bound session raises 1, 2 and 5).

**`tests/integration/test_preflight.py`** — module fixture `backup_template` restores the newest dump
**without** pending migrations; `backup` is a per-test clone with a sync dict-row connection.
`run_preflight()` executes the shipped file in a `READ ONLY` transaction as a prepared statement (so
it cannot hold a second command). The `legacy_run` fixture builds a small old-style run with SQL.

## Deviations from the design

- `06` T0.2 / T2.2 / T3.1, `07` T-REG: **all six tests say `fixed by T2.2`.** They edit the library
  plan, so copying the plan per run fixes all of them (verified as above). T2.2 must remove all six
  markers, not only R1/R2; T3.1 has none left to remove and proves lineage identity with
  T-INT-ID-01…08. Docs `06`/`07` not edited.
- `02` §4.1: the pre-flight audits only runs without a run plan, the set 0019 converts (`02` §4.2).
  Without this, a run created by T2.2 from a plan with an empty slot would block the deploy.
- `06` T0.2: verified against the 2026-11-25 dump, not 2026-11-19.

## Known gaps / follow-ups

- The five checks do not verify that references F7–F11 (prescribed units, slots, variants, sets,
  substituted variants) lie in a revision the run uses. `02` §4.3 verification (T2.1) should catch
  any leftover.
- `test_preflight.py` needs a dump from **before** 0019. Once a converted backup is the newest one,
  T-PRE-01 fails its "has unconverted runs" guard and the SQL-built run violates the new NOT NULL
  columns: pin the module to the last older dump, or retire it with the pre-flight (owner: whoever
  commits that backup, at the latest T6.1).
- `test_preflight.py` imports private helpers from `conftest.py` (`_dump_path`, `_restore`, …).
