# T2.2 — Run creation and deletion with run plans

- **Date:** 2026-11-28
- **Branch / commit:** `impl/T2.2-run-creation` / the commit that adds this file
  (`feat(be): give every new run its own run plan`), based on `master` `407323b`
- **Status:** done (awaiting review)

**Finding:** the demo plan in the dumps (library plan 6, revisions 6 and the RELEASED 25) is **not
executable**: 5 DEFAULT variants have no sets. From now on a run can no longer be started from it
(422 `plan_not_executable`, Q1). Every revision that a real run uses, and every other library
revision in `agonez_db_backup_2026-11-28.sql`, is executable (checked with `validate_executable`
on the restored dump).

## What exists now

No migrations. Works on 0018 with the unchanged positional read code. Legacy runs
(`run_plan_id` NULL) behave exactly as before.

**`be/src/agonez_api/modules/plans/executability.py`** (pure, no I/O)

| Name | What it does |
| --- | --- |
| `validate_executable(rows: DraftRows, *, expected_day_count=None) -> list[ExecutabilityIssue]` | The rules of `03` §3. `expected_day_count=None` skips `day_count_changed`. Issues come in plan order (plan-level first, then by day ordinal, then slot ordinal). |
| `ExecutabilityIssue(code, path, day_ordinal, slot_ordinal, message)` | `as_dict()` gives the API shape `{code, path, day_ordinal, slot_ordinal, message}`. |
| `summarize_issues(issues) -> str` | `"This plan cannot be started yet. "` + the first 3 messages + `" And N more problem(s)."`. |

Issue codes, paths and ordinals (stored, zero-based ordinals in paths; messages count from 1):

| Code | `path` | `day_ordinal` / `slot_ordinal` | Message example |
| --- | --- | --- | --- |
| `day_count_changed` (only with a count) | `days` | — / — | `The plan has 3 days; this run needs exactly 4 days.` |
| `no_workouts` (also for a revision without days) | `days` | — / — | `The plan has no workout: add exercises to at least one day.` |
| `workout_without_exercises` | `days.<d>.workout_unit` | d / — | `Day 3 "Core": the workout has no exercises.` |
| `slot_without_exercise` (≠ exactly one DEFAULT) | `days.<d>.workout_unit.exercise_slots.<s>` | d / s | `Day 1 "Upper", exercise 2: choose the exercise to perform.` |
| `exercise_without_sets` (DEFAULT only; a FALLBACK without sets is fine) | same slot path | d / s | `Day 1 "Upper", exercise 3 "cable_fly": the exercise has no sets.` |
| `duplicate_lineage` (units and slots, per revision) | unit or slot path | d / s or — | `…: the workout shares its identity with another workout (internal error, please report it).` |

Labels: the workout name (else the day name); the slot name, else the DEFAULT's exercise slug.

**`be/src/agonez_api/modules/execution/repository.py`**

- `create_plan_run`: after the microcycle-count check, in the existing transaction:
  `lock_library_source` → `create_run_plan` → `_load_revision_tree(r1)`, then today's algorithm with
  `initial_plan_revision_id = r1`, `run_plan_id = run plan`, microcycles on r1, sessions on r1 rows.
  Tracks: `plan_lineage_key` = the r1 unit / slot lineage key, `logical_key` still `day:N` / `slot:N`.
  Setup notes are seeded as before. `PlanRunCreate` and `preview_plan_run` are unchanged (the
  preview still reads the requested revision and stays permissive).
- `_load_revision_tree` also returns `lineage_key` on workouts and slots (additive; `_project` does
  not use it).
- `delete_plan_run`: reads `run_plan_id` with the `FOR UPDATE`; after deleting sessions and the run,

  children and the image cascade; plans promoted from it keep their rows (`source_plan_id` and their
  `based_on_revision_id` become NULL). Still one call (`RunManagerDialog` unchanged).

Visible API effects for a new run: `run.plan` = the run plan (`plan_id`, `code` `P0xx` of the run
plan, same name); `initial_revision` = r1. Deleting a library plan whose runs were all created
after this change answers **204** (its runs reference only their run plans).

## Deviations from the design

Small, local; docs `00`–`07` not edited:

- `02` §3.2/§3.3: `create_run_plan(connection, *, source: Row)` takes the row returned by the new
  `lock_library_source` (step 1 of §3.3) instead of `source_revision_id`, so the source is read
  once under its lock. `not_executable(code, issues)` lives in the same file. `RunPlanRepository`
  is built by `ExecutionRepository`, not wired in `app.py`.
- `03` §3: path granularity fixed as above (plan-level issues `days`; workout issues
  `days.<d>.workout_unit`; slot and set issues at the slot path). The error `message` summarises
  the first three issues (the New Run screen shows `message` as is).
- `04` §2: `plan_revision_not_library` carries `details {plan_revision_id, plan_id}`; an unknown
  revision keeps today's 404 `plan_revision_not_found`.
