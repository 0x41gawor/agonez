## What exists now

No migrations, no new routes. Library plans behave as before, except that deleting a library
plan whose rows a run still uses now answers **409** instead of 500. Production has no run-scope
plans yet, so every scope guard is inert on today's data.

**`be/src/agonez_api/modules/plans/repository.py`**

| Name | What it does |
| --- | --- |
| `load_revision_rows(connection, revision_id) -> DraftRows` | Module-level, public. Loads **any** revision (DRAFT or RELEASED). Header: `id`, `name`, `description`, `accent`, `image_checksum`, `scope`, `source_plan_id`, `plan_run_id` (read-only `LEFT JOIN exec.plan_runs ON run_plan_id = p.id`), `revision_id`, `revision_no`, `lock_version`, `revision_status`. Workout units and slots now carry `lineage_key` (UUID). `load_step_kg` is still the effective value (`COALESCE` with the resistance-source default). Missing revision → `PlanRevisionNotFoundError` (404 if it reaches the API). |
| `copy_revision(connection, source_revision_id, target_revision_id, *, regenerate_progression_ids) -> RevisionCopyMap` | Module-level wrapper of `plans.copy_revision_tree(%s::integer, %s::integer, %s::boolean)` in the caller's transaction. Returns `{entity: {source_id: target_id}}` for `day`, `workout_unit`, `exercise_slot`, `exercise_variant`, `set_infra` (always all five keys). psycopg errors pass through unchanged (`ObjectNotInPrerequisiteState`, `NoDataFound`, `NullValueNotAllowed`). |
| `PlanRepository._find_draft_revision(connection, plan_id)` | The DRAFT's id, or `PlanDraftNotFoundError`. `_load_draft_rows` = this + `load_revision_rows`. |
| `PlanRepository.duplicate_plan` | Uses `copy_revision(…, regenerate_progression_ids=True)`; the Python remapping `_copy_draft_tree` is gone (and `uuid4`). Inserts `scope = 'library'` explicitly; the "`<name> copy`" rule now looks only at **library** names. `source_plan_id` stays NULL (T5.1 sets it). |
| `list_plans` | `WHERE p.scope = 'library'`; returns `scope`, `source_plan_id`. |
| `get_plan` | Also returns `scope`, `source_plan_id`, `plan_run_id`. |
| `delete_plan` | One transaction: plan row `FOR UPDATE`; missing → `PlanNotFoundError`; `scope <> 'library'` → `PlanScopeError` ("Run plans are deleted together with their plan run"); `DELETE … WHERE id = %s AND scope = 'library'`; a `ForeignKeyViolation` (a run's RESTRICT FKs) → `PlanInUseError` ("Plan N is still used by a plan run"). |
| `create_plan`, `import_plan` | Insert `scope = 'library'` explicitly. |

**`be/src/agonez_api/modules/plans/fingerprint.py`** — `definition_fingerprint(rows, *,
include_progression_ids=True) -> str`: hex SHA-256 of canonical JSON (sorted keys, compact
separators) of the tree days → workout units → slots (target muscles, variants → sets), children
in ordinal order (ties by content). It takes **every** loader column except row ids, parent ids
and join-derived slugs (`exercise_slug`, muscle `slug`); the header is ignored entirely (plan
identity fields, revision id/number/lock version/status). Numbers are normalised decimal strings
(`2.5` = `Decimal("2.500")`), UUIDs strings. `include_progression_ids=False` is for comparing a
copy with fresh progression ids (duplicate, promotion: T-INT-PR-01).

**Schemas / service / app** — `PlanScope` enum (`library`, `run`). `PlanDraftArtifact` and
`PlanDetail` gain required `scope`, `source_plan_id`, `plan_run_id`; `PlanSummary` gains `scope`,
`source_plan_id`. `PlanDraftUpdate` accepts and ignores all three (GET→PUT round trip).
`assemble_draft` fills them from the header. New exceptions `PlanRevisionNotFoundError` (404),
`PlanScopeError` and `PlanInUseError` (both 409 `{"detail": …}`). The delete route got an OpenAPI
description of the two 409 cases.

## Deviations from the design

- `07` T-API-PLANS-03 / `04` §2 ("library plans with runs are now deletable"): **409
  `PlanInUseError`**, not 204. Runs still reference library rows until T2.2 (new runs) and 0019
  (T2.1, old runs); 204 is impossible before that, and the task asked for a 4xx instead of the 500.
  Docs not edited (the end state they describe is unchanged).
- `02` §3.1 Revision loader / Copy: `load_revision_rows` and `copy_revision` are **module-level
  functions** in `plans/repository.py` (the signatures have no `self`, and Execution needs them
  without a `PlanRepository`). The header also has `revision_status`. New `PlanRevisionNotFoundError`.
- `02` §3.1 Fingerprint: uses the **effective** `load_step_kg` (as loaded) and the catalog ids
  (`exercise_id`, `muscle_id`) instead of slugs; adds `include_progression_ids` (T5.1/T-INT-PR-01).
  Reason: an editor GET→PUT turns a stored NULL step into the explicit default (copies keep the
  NULL), which must not count as an unapplied change.
- `07` T-IMM-03: scans every `.py` under `src/agonez_api` (not only `modules/`), also catches
  `TRUNCATE`, unqualified plan table names and dynamic targets, and lists today's two
  plan-level writers that the matrix does not name (`delete_plan_image`, the identity
  `UPDATE plans.workout_plans` in `save_draft`). SQL migrations are out of its scope.
- Duplicate name rule counts only library names (inert today; run plans repeat library names).
