## Deviations from the design

- **Test-only pre-T2.2 stand-in — removed at the rebase.** Before T2.2 was on the branch, the
  converted template needed `BEFORE INSERT` triggers so that `master`'s old run creation satisfied
  the new NOT NULL columns. Since the rebase onto `e79fc1d` it is deleted; nothing of it remains.
- **T2.2's legacy-run tests run before 0019** (`test_api_plans_03_…` split, the legacy half and
  `test_deleting_a_legacy_run_keeps_its_library_plan` marked `before_migration`): a run without
  `run_plan_id` cannot exist after 0019.
- **Two T1.1 tests run on the pre-0019 database** (`before_migration` marker; see above): they assert
  0018's "invisible to today's code" state, which 0019 ends by design.
- **06 T2.1 names the 2026-11-19 backup**; verified on 2026-11-28 (the newest; it records 0018) and
  2026-11-25. Same seven legacy runs and the same acceptance facts; no id adjusted.
- **Small additions to `02` §4.2 / §4.3** (SQL there is conceptual): explicit table locks; the map
  also records `workout_plan` and `plan_revision` rows (the DRAFT copy is not mapped), with a PK and an
  entity `CHECK`; `released_at` is midnight UTC of the first microcycle start; revision `snapshot`
  NULL and `lock_version` 1 as run creation does; a run whose revisions span two plans, or whose start
  plan is not library scope, raises; the verification checks the run's **own** plan (stronger than
  "not library") for every run, so a malformed T2.2 run would also block the deploy; lineage
  uniqueness is checked per entity for run-plan revisions; the preflight error lists every finding.
- **Reference pinning is dynamic:** "the newest dump without 0019" is computed from each dump's
  migrations table rather than a fixed file name, so it stays correct as backups are committed.

Docs `00`–`07` not edited (no contract change).
